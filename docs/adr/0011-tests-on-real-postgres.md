# ADR-0011. Тесты сервисов и адаптеров — на реальном Postgres

Статус: принято · Дата: 2026-09-29

## Контекст

Ключевые правила опираются на свойства Postgres: уникальность
`(shopping_list_id, name_normalized)`, `numeric`, `jsonb`, транзакционность событий и outbox,
блокировки при ротации refresh-токенов. Моки БД или SQLite эти свойства не воспроизводят и дают
зелёные тесты при сломанной логике. Фронтенд проверяется вручную (спец. §11), поэтому
бэкенд-тесты — основная защита.

## Решение

### Уровни и структура

```
tests/
  unit/           без БД: normalization, quick_add, merge_item, загрузчик CIMD, OAuth-утилиты
  integration/    сервисы и репозитории на Postgres; миграции
  api/            REST — httpx.AsyncClient + ASGITransport
  mcp/            MCP — клиент из SDK в том же процессе
  factories.py    make_user(), make_shopping_list(), make_item(shopping_list_id, ...)
  conftest.py
```

- `scripts/test.sh unit` — только быстрые тесты без Docker; без аргументов — весь набор.
- Таблица примеров из спец. §5.6 переносится в `unit/` целиком (`pytest.mark.parametrize`).
- Фабрики — простые async-функции через репозитории; factory_boy / polyfactory не используем.
  Общих фикстур-«миров» с десятком объектов избегаем.
- Моки собственных модулей (репозиториев, сервисов) не используются.

### Postgres

- `testcontainers`, один контейнер на тестовую сессию, образ **`postgres:18-alpine`** —
  тот же тег, что в `docker-compose`, берётся из одного места.
- Схема создаётся миграциями Alembic (`upgrade head`) один раз на сессию, не `create_all`.

### Изоляция тестов

- **По умолчанию — внешняя транзакция с откатом.** Фикстура открывает соединение и транзакцию,
  `session_factory` (ADR-0004) подменяется на привязанную к этому соединению с
  `join_transaction_mode="create_savepoint"`: `commit()` внутри `unit_of_work` фиксирует только
  savepoint, после теста всё откатывается.
- **`@pytest.mark.real_commits` — для тестов конкурентности**, которым нужны несколько настоящих
  соединений: гонка двух refresh, `SELECT … FOR UPDATE` при ротации, параллельное объединение
  одной позиции. Такой тест работает с обычной `session_factory` и настоящими коммитами, после
  него фикстура выполняет `TRUNCATE … RESTART IDENTITY CASCADE` по всем таблицам. Таких тестов —
  единицы.

### Миграции — `upgrade` и `downgrade`, stairway-тест

- Каждая миграция содержит рабочий `downgrade` (ADR-0013).
- **Stairway-тест**: для каждой ревизии по порядку — `upgrade` → `downgrade` → `upgrade`.
  Ловит забытые в `downgrade` объекты (тип, индекс, ограничение) и миграции, которые нельзя
  применить повторно.
- `alembic check` после `upgrade head` — модели и миграции совпадают.
- Миграционные тесты работают с отдельной пустой базой в том же контейнере, а не с базой
  остальных тестов.

### Время

- `time-machine` подменяет текущее время в Python для тестов сроков жизни (access token, код
  авторизации, окно повтора refresh, повторы push).
- **Правило для кода**: сроки и окна сравниваются в Python (`datetime.now(UTC)`), а не через
  `now()` в SQL — время Postgres тестом не заморозить. `server_default=func.now()` для
  `created_at` допустим: это метка, а не основание для решений.

### Внешние системы и сеть

- **Push** (`pywebpush`) — мок на границе: проверяется, что и кому отправлено, и реакция на
  ответы 201 / 404 / 410 / 5xx.
- **CIMD-документы** — `respx` перехватывает запросы `httpx`: загрузчик выполняет свой настоящий
  код (размер, `client_id`, кэш) без выхода в сеть. Защита от SSRF проверяется на уровне
  резолва адреса.
- **Сеть запрещена** плагином `pytest-socket` (`--disable-socket --allow-hosts=127.0.0.1,localhost`
  и адрес контейнера): тест, случайно пошедший в интернет, падает.
- Параллельный запуск (`pytest-xdist`) не используем, пока весь набор укладывается в десятки секунд.

## Последствия

- Для интеграционных тестов нужен запущенный Docker — локально и в CI; юнит-тесты работают без него.
- Тесты медленнее юнит-тестов на моках, но при таком объёме модели это секунды.
- Каждая миграция стоит дороже: `downgrade` пишется и проверяется наравне с `upgrade`.

## Как проверяется

- `scripts/check.sh` запускает весь набор (ADR-0007).
- Ревью: `unittest.mock` / `monkeypatch` на собственные модули — повод переписать тест;
  `now()` в SQL-условиях по срокам — ошибка.
