# ADR-0016. Граница транзакции MCP учитывает сериализованный tool error

Статус: принято · Дата: 2026-10-03

## Контекст

ADR-0004/0010/0012 требуют общую middleware `tools/call`: пользователь, UoW и перевод
доменных ошибок. На установленном официальном `mcp` 2.2.0 обработчик SDK перехватывает
исключение инструмента до выхода в middleware, а runner сериализует результат в словарь
с `isError`. Обычный выход из UoW после такого результата коммитил бы частичные записи.
Поднятый вне обработчика ToolError также не проходит его обычный перевод в tool result.

## Решение

Уточняем механизм ADR-0012 без изменения бизнес-логики и внешнего контракта:

- Единая обёртка `domain_errors` применяется при регистрации инструментов. Она переводит
  DomainError в ToolError с message/hint/details до перехвата SDK; неожиданный сбой —
  безопасное сообщение «Внутренняя ошибка» и серверный журнал. SDK валидирует аргументы.
- Middleware `tools/call` открывает UoW и `acting_as`, вызывает `call_next`, проверяет
  сериализованный `isError` или модель CallToolResult.is_error. При ошибке поднимает
  внутреннее исключение, чтобы UoW откатился, затем возвращает исходный error result.
- Успешный результат выходит только после завершения commit. Ошибка commit возвращает
  безопасный tool error. Отмена задачи распространяется после rollback.
- Верификатор PAT открывает отдельную короткую UoW на HTTP-запрос: last_used_at фиксируется
  независимо от успешности инструмента. Middleware не держит ORM между запросами.
- Корневой alias `/.well-known/oauth-protected-resource` использует тот же endpoint SDK,
  что `/.well-known/oauth-protected-resource/mcp`; ответы не дублируются вручную.
- Streamable HTTP используется в stateless-режиме с JSON-ответами: live-обновления приложения
  идут по REST SSE, инструменты не требуют сессий MCP. Legacy handshake также проверяется.

MCP SDK зафиксирован lockfile на 2.2.0. При обновлении обязательны transport/rollback tests:
его middleware API provisional, форму результата нельзя выводить только из type hints.

## Последствия

Обработчики остаются тонкими, не содержат локальных try/except и не управляют commit.
Дополнительная общая обёртка сохраняет hints, а проверка результата предотвращает
тихий commit при tool error. Root mount располагается после REST-маршрутов;
добавляемые тестами probe routes проверяются в API-only fixture без catch-all mount.

## Как проверяется

- На реальном Postgres: запись позиции и события перед DomainError/неожиданной ошибкой
  полностью откатывается, SSE не публикуется.
- Forced commit failure не выдаёт успешный результат и не раскрывает диагностические данные.
- Отмена вызова откатывает запись; ContextVar пользователя и БД сбрасываются.
- Два параллельных HTTP-вызова с PAT разных пользователей сохраняют свои списки и источники.
- SDK-клиент через реальный HTTP-сокет, modern discovery и legacy handshake.

Первичные источники: исходники установленного SDK 2.2.0 (`server/runner.py`,
`server/mcpserver/server.py`, `tools/base.py`) и
[официальная документация middleware](https://py.sdk.modelcontextprotocol.io/advanced/middleware/).
