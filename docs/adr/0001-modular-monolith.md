# ADR-0001. Модульный монолит с фиксированным направлением зависимостей

Статус: принято · Дата: 2026-09-29

## Контекст

Нагрузка ничтожная, один пользователь, один VPS (спец. §3). Отдельные сервисы, очереди и Redis
не оправданы. Но у системы две «двери» (REST и MCP), фоновый push-воркер и собственный
OAuth-сервер — без явных границ модули быстро начнут импортировать друг друга как придётся.

## Решение

Весь бэкенд — один Python-пакет и один процесс FastAPI. Push-воркер — asyncio-задача, которую
запускает и останавливает `lifespan` приложения. SSE-хаб — объект в памяти этого же процесса.

Код разбит на слои; слой может импортировать только слои ниже себя:

| Слой | Модули | Что делает |
|---|---|---|
| Адаптеры | `api`, `mcp_server` | Разбор запроса, аутентификация, вызов сервиса, форма ответа |
| Сервисы | `services.shopping_list_service`, `services.auth`, `services.events`, `services.push` | Бизнес-правила, запись событий, токены |
| Данные | `db` (модели, репозитории, сессия) | Хранение и запросы |
| Схемы | `schemas` | Pydantic-схемы; нормализация — в валидаторах |
| Правила | `domain.normalization`, `domain.quick_add`, `domain.errors` | Чистые функции и исключения: без БД и ввода-вывода |

`config` доступен всем слоям.

- Схемы стоят ниже `db`, потому что репозитории принимают их в `add` / `update` (ADR-0005).
- Сервисы и правила не импортируют FastAPI, Starlette, MCP SDK.
- `api` и `mcp_server` не импортируют друг друга и не обращаются к репозиториям и моделям
  напрямую — только к сервисам (ADR-0008). Два узких исключения: `db.session.unit_of_work`
  (открыть единицу работы, ADR-0004) и подписка на SSE-хаб из `events` (эндпоинт `/api/events`).
- Внутри слоя сервисов: `push` → `events`; `shopping_list_service` → `events`, `auth`
  (текущий пользователь); `auth` не импортирует `shopping_list_service`.
- Дерево пакетов — ADR-0014.

## Последствия

- Деплой — один контейнер `backend`. Push-воркер при необходимости выносится в отдельный контейнер
  из того же образа с другой командой запуска — код воркера для этого не меняется, потому что он
  не зависит от HTTP-слоя.
- SSE-хаб в памяти работает только при одном процессе uvicorn. Масштабирование на несколько
  процессов потребует внешнего брокера — осознанно вне v1.

## Как проверяется

`import-linter` с контрактами «слои» и «запрещённые импорты» в `pyproject.toml`; запускается
в общей команде проверки (ADR-0007).
