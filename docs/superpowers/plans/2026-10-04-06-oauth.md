# Этап 6 — OAuth Authorization Server

Основа: ADR-0010, спецификация §4, §6.2 и §9. Backend остаётся единственным AS;
MCP SDK проверяет наши непрозрачные access tokens. PAT и cookie-вход сохраняются.

## Существенные решения

- Каждое согласие создаёт семейство (`oauth_grants`). Блокировка его строки сериализует
  refresh и отзыв, в том числе двух разных потомков одного refresh в окне повтора.
- Отзыв при replay возвращается как результат сервиса, чтобы транзакция сохранила отзыв
  перед ответом `invalid_grant`; исключение откатило бы защитное действие.
- Запрос согласия привязан к браузеру отдельной HttpOnly cookie; подтверждение требует
  сессии и `X-Device-Id`. Первый просмотр связывает запрос с вошедшим пользователем.
- CIMD resolver проверяет все адреса и передаёт коннектору те же IP без повторного DNS.
  Редиректы, proxy из окружения и сжатые ответы не используются.
- Владельцу остаётся ручная проверка браузера и подключение реальных MCP-клиентов.
