# ADR-0002. Pydantic-схемы на границах и строгая типизация бэкенда

Статус: принято · Дата: 2026-09-29

## Контекст

Фронтенд строится по макету и проверяется вручную, поэтому ошибки контракта должны ловиться
до запуска — типами. Одни и те же данные уходят через REST, MCP, SSE и push; если их форма
описана в нескольких местах, описания разойдутся.

## Решение

- **Pydantic v2** описывает всё, что пересекает границу модуля или сериализуется: тела запросов
  и ответов REST, аргументы и результаты MCP-инструментов, события SSE и payload событий в БД,
  настройки (ADR-0006).
- Схемы (`ItemCreate`, `ItemUpdate`, `ItemRead`, `AddItems`, `QuickAddResult`, `Source`, …) живут
  в пакете `schemas` — ниже репозиториев (ADR-0001), потому что `add` / `update` принимают их
  (ADR-0005). REST и MCP переиспользуют их, а не объявляют свои копии. Схема, специфичная для
  одного адаптера (например, форма ответа логина), живёт в адаптере.
- Нормализация входных данных — в валидаторах схем через `domain.normalization`: после валидации
  `ItemCreate` уже содержит `name_normalized` и количество в базовой единице (спец. §5.1–5.2).
- Именование: `<Сущность>Create` / `Update` / `Read`; `Read`-схемы строятся из ORM через
  `model_validate(obj, from_attributes=True)` (`ConfigDict(from_attributes=True)`).
- **ORM-модели не выходят за пределы сервисного слоя.** Репозитории возвращают ORM-модели сервису
  (ADR-0005), сервис наружу отдаёт только Pydantic-схемы.
- Внутренние значения, которые не сериализуются (результат разбора строки
  внутри `quick_add`), — `@dataclass(frozen=True, slots=True)` или Pydantic, по удобству.
- **mypy в режиме `strict`** с плагином `pydantic.mypy`. ORM-модели — в стиле SQLAlchemy 2.0
  (`Mapped[...]`, `mapped_column`), без плагина SQLAlchemy.
- `Any`, `cast` и `# type: ignore` допускаются только с комментарием-причиной;
  `type: ignore` — всегда с кодом ошибки (`# type: ignore[arg-type]`).

## Последствия

- Изменение формы данных — это изменение одной схемы; mypy и генерация TS-клиента (ADR-0009)
  показывают все места, которые нужно поправить.
- Больше шаблонного кода при переходе ORM → схема; это осознанная плата за изоляцию ORM.

## Как проверяется

- `mypy --strict` в общей команде проверки (ADR-0007).
- mypy strict требует аннотаций у всех функций (`disallow_untyped_defs`).
- `import-linter`: `api` и `mcp_server` не импортируют `db.models` (ADR-0001).
