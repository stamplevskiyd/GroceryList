# Этап 7 — первый рабочий интерфейс

2026-10-04 владелец выбрал настоящий список поверх готового API, чтобы уже сейчас
проверить поведение в браузере. Это минимальная часть этапа 7, не весь PWA.

## Реализовано

- React, openapi-fetch и openapi-react-query / TanStack Query по ADR-0009.
  Контракт берётся из сгенерированного OpenAPI, cookie не доступны JavaScript.
- Регистрация с подтверждением пароля и автоматическим входом; личный список.
- Вход, выход с очисткой кэша, выбор доступного списка.
- Быстрый ввод: строка передаётся серверу, включая разбор количества и объединение.
- Отметка купленного и возврат, удаление с подтверждением, очистка всего купленного.
- Фильтр по нескольким тегам; новая позиция получает выбранные теги.
- Количество, единицы, заметки и источник MCP отображаются в строке.
- Карточка по нажатию на название: редактирование названия, количества, единицы
  (включая свою), тегов с подсказками и заметки; сохранение и удаление.
  На телефоне открывается снизу, на ноутбуке — модальное окно. Несохранённые изменения
  требуют подтверждения закрытия. Ошибка и SSE не стирают черновик: PATCH отправляет
  только изменённые поля (количество и единицу вместе). Одновременное изменение одного
  поля остаётся за последним сохранением. Удалённую в другой вкладке позицию сохранить нельзя.
- SSE инвалидирует запрос списка; после восстановления соединения список загружается
  заново. Есть ручное обновление и сообщения об ошибках. Неуспешный ввод не стирается.
- Адаптивная светлая/тёмная тема на дизайн-токенах существующих макетов.
- Экран OAuth переведён на общий типизированный клиент.

Витест/DOM-проверки: вход → добавление → купленное → выход, сохранение ввода при ошибке,
SSE и безопасное текстовое отображение имени. Проверки карточки покрывают сохранение,
очистку полей, свои единицы, дробное количество с запятой, ошибку с повтором,
отмену закрытия/удаления и обновление/удаление из другой вкладки.
Включены в `scripts/check.sh`.
Это проверки логики; визуальная браузерная приёмка остаётся за владельцем.

## Ручная приёмка

Открыть https://grocery.94-159-101-162.sslip.io после публикации `v0.4.0`:

1. Войти; добавить `молоко 2 л`, убедиться в количестве и единице
   (сервер нормализует литры: в этой версии отображается `2 000 мл`).
2. Обновить страницу — позиция сохраняется на сервере.
3. Открыть вторую вкладку. В первой отметить покупку; во второй она переходит в купленное.
4. Раскрыть «Куплено», вернуть позицию в покупки, удалить её с подтверждением.
5. Выйти: список исчезает, показана форма входа.
6. Нажать «Нет аккаунта? Зарегистрироваться», создать новый аккаунт; проверить новый
   пустой список и отсутствие покупок предыдущего пользователя. Повтор занятого логина
   должен показать ошибку, несовпадающее подтверждение пароля — остановить отправку формы.
7. Нажать название покупки; изменить количество на `1,5`, выбрать `кг`, добавить тег
   и заметку. Сохранить, обновить страницу, снова открыть карточку: данные сохранились
   (сервер преобразует `1,5 кг` в `1 500 г`). Проверить свою единицу и очистку полей.
8. Изменить заметку, закрыть карточку и отказаться от потери изменений — текст остаётся.
   Во второй вкладке изменить количество: в первой черновик заметки сохраняется.
9. Проверить удаление из карточки с отменой и подтверждением; на телефоне проверить
   прокрутку длинной формы и доступность кнопки сохранения при открытой клавиатуре.

Для localhost `npm run dev --prefix frontend` проксирует API на `localhost:8000`.
Полноценный cookie-вход в Safari проверяется по HTTPS. Сертификаты ОС не меняются.
