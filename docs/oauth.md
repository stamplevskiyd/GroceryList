# OAuth для MCP

GroceryList выдаёт доступ MCP-клиентам через собственный Authorization Server.
Пользователь входит своим логином и паролем и подтверждает подключение приложения.
Вход через Google/GitHub не добавляется. PAT и cookie-сессии продолжают работать.

OAuth входит в код начиная с релиза `v0.2.0`. Состояние публикации — в
[инструкции деплоя](deployment.md). Backend и Caddy обновляются вместе;
миграция `0006` применяется entrypoint.

## Подключение

Адрес MCP — `<APP_PUBLIC_URL>/mcp`. Метаданные AS находятся по
`/.well-known/oauth-authorization-server`, resource metadata — по
`/.well-known/oauth-protected-resource/mcp` (также есть корневой alias).

Поддерживаются публичные клиенты (`token_endpoint_auth_method=none`) без client secret:

1. CIMD: `client_id` — HTTPS URL документа с совпадающим `client_id`, `client_name`
   и `redirect_uris`. Сервер загружает документ и кэширует метаданные.
2. DCR: `POST /oauth/register` с JSON, например
   `{"client_name":"Мой клиент","redirect_uris":["http://127.0.0.1:8765/callback"]}`.
   Ответ 201 содержит выданный `client_id`.
3. Клиент открывает `/oauth/authorize` с `client_id`, `redirect_uri`, `response_type=code`,
   `resource=<APP_PUBLIC_URL>/mcp`, `code_challenge`, `code_challenge_method=S256`,
   `scope=shopping_list offline_access` и случайным `state`.
4. Браузер переходит на `/consent?request=<UUID>`: при необходимости вход, затем имя
   приложения, адрес возврата и кнопки «Разрешить»/«Отклонить». Для loopback показано
   предупреждение о локальной программе. Прямое открытие `/consent` не запускает подключение.
5. Клиент получает callback с `code`, исходным `state` и `iss`. Отказ возвращает
   `error=access_denied`, `state`, `iss`. Клиент проверяет state и issuer.
6. `POST /oauth/token`, форма `application/x-www-form-urlencoded`:
   `grant_type=authorization_code`, `client_id`, `code`, `redirect_uri`, `code_verifier`,
   `resource`. Ответ содержит `access_token`, `token_type=Bearer`, `expires_in`, `scope`
   и, при `offline_access`, `refresh_token`.
7. MCP-запросы используют `Authorization: Bearer <access_token>`.

Redirect URI сравнивается точно; только для HTTP loopback (`localhost`, `127.0.0.1`, `::1`)
может отличаться порт. HTTPS обязателен для остальных адресов. `resource` во всех запросах —
ровно канонный MCP URL без завершающего `/`.

## Обновление и отзыв

`POST /oauth/token` с `grant_type=refresh_token`, `client_id`, `refresh_token`, `resource`
выдаёт новую пару. Клиент заменяет сохранённый refresh. Scope при обновлении можно опустить
или передать прежний; изменение разрешений требует нового согласия.

Access живёт до часа, код — 5 минут, запрос согласия — 10 минут. `offline_access` даёт
семейству абсолютный срок 30 дней от согласия: ротация его не продлевает. Без этого scope
refresh не выдаётся. Сроки настраиваются через `AUTH_OAUTH_*` в `.env.example`.

Повтор старого refresh в течение 60 секунд от первой ротации допускается; после этого
отзывается всё семейство, ответ — `invalid_grant`. Повтор использованного кода с корректными
параметрами также отзывает семейство. Эти отзывы сохраняются в БД до возврата ошибки.

`POST /oauth/revoke` принимает форму `client_id`, `token`, необязательный `token_type_hint`.
Refresh отзывает всё семейство (включая потомков), access — только данный access.
Неизвестный токен возвращает 200 без раскрытия его существования.

Cookie-защищённый REST API:

| Метод и путь | Назначение |
|---|---|
| `GET /api/oauth/requests/{id}` | Данные для экрана согласия |
| `POST /api/oauth/consent` | `{request_id, allow}` → `{redirect_url}` |
| `GET /api/oauth/connections` | Подключённые приложения текущего пользователя |
| `DELETE /api/oauth/connections/{id}` | Отозвать все согласия пользователя этому клиенту |

Мутации требуют `X-Device-Id`. В DELETE используется `id` из списка подключений,
не строковый OAuth `client_id`. Экран управления подключениями появится вместе с PWA;
сейчас API доступен в Swagger.

## Ручная проверка в браузере

После обновления сервера из корня репозитория выполните:

```bash
uv run --project backend python scripts/check_oauth_browser.py https://grocery.94-159-101-162.sslip.io
```

Команда печатает ссылку. Откройте её в Safari или другом браузере **на том же компьютере**,
войдите существующим пользователем, проверьте имя «Ручная проверка GroceryList» и разрешите
доступ. Браузер вернётся на временный localhost callback. Терминал проверит обмен кода,
MCP handshake, чтение списка и ротацию refresh, затем отзовёт тестовое подключение.
Содержимое списка и секретные токены не печатаются. Ожидание решения — до 10 минут.
Повторите запуск и отклоните доступ: сообщение об отказе ожидаемо, токены не выдаются.
Проверка чтения предполагает один доступный список пользователя.

Локально можно передать другой HTTPS origin с доверенным браузеру сертификатом.
`http://localhost:8080` годится для просмотра статики, но полноценный вход в Safari требует
HTTPS: cookie сессии и запроса согласия имеют `Secure`. Команда не меняет сертификаты
и не открывает браузер автоматически.

Для окончательной приёмки отдельно подключите реальный MCP-клиент по `/mcp`, вызовите
инструмент, затем удалите подключение через API и убедитесь, что старый access получает 401.
Эти ручные сценарии ещё не выполнены; автоматические тесты не заменяют их.

## Реализация и ограничения

В БД хранятся только SHA-256 кода и токенов. Запрос согласия связан с браузером отдельной
HttpOnly cookie и с пользователем при первом авторизованном просмотре. Семейство хранится
в `oauth_grants`; блокировка строки сериализует refresh и отзыв. Уже начатый MCP-вызов
может завершиться после отзыва, новые HTTP-запросы будут отклонены.

CIMD: HTTPS, проверка всех DNS-адресов с закреплением проверенных IP при соединении,
запрет внутренних адресов, перенаправлений и сжатия; по умолчанию 64 KiB и 5 секунд.
Кэш учитывает Cache-Control/Age, максимум час, при отсутствии директив — 5 минут.

Публичные OAuth-маршруты ограничены 60 запросами на IP и 300 на маршрут в минуту,
состояние лимитера — в одном процессе. Backend не доверяет forwarded-заголовкам;
за Caddy клиенты делят лимит IP прокси. Истёкшие записи пока не удаляются фоновым заданием.

Архитектура и причины решений — [ADR-0010](adr/0010-auth.md).
